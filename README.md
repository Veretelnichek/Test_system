# Vector — обучающая платформа

Веб-приложение для организации учебного процесса между куратором и учениками: Kanban-доски,
модули, проверка заданий, комментарии, история изменений, уведомления, умные напоминания и
аналитика. Интерфейс на русском языке, тёмная тема, адаптивная вёрстка.

## Возможности

- **Две роли.** Ученик работает со своей доской и отправляет задания на проверку. Куратор ведёт
  учеников, создаёт модули и задания, проверяет работы и видит аналитику.
- **Реальная авторизация.** Supabase Auth (email + пароль), подтверждение email, восстановление
  пароля, защита маршрутов. Куратор после регистрации ожидает подтверждения администратора.
- **Kanban с drag-and-drop.** Пять статусов: бэклог → в работе → на проверке → готово / на
  доработке. Переходы проверяются на сервере (RPC), а не только в интерфейсе.
- **Карточка задания.** Описание, дедлайн, модуль, комментарии и полная история переходов.
  Возврат на доработку требует комментарий не короче 10 символов.
- **Очередь проверки.** Просроченные проверки (более 24 часов) выделяются, доступны быстрые
  действия «Принять» и «Вернуть».
- **Ученики и приглашения.** Коды приглашений со сроком действия, ссылка на регистрацию,
  привязка ученика к куратору, открепление.
- **Уведомления и Realtime.** Новые проверки, возвраты, комментарии, дедлайны. В Supabase
  обновления приходят через Realtime; локально — через событие `storage`.
- **Умные напоминания.** Задание без движения 48 часов и проверка дольше 24 часов создают
  уведомление один раз за цикл (идемпотентность через `reminder_events`).
- **Аналитика.** Медианный цикл, среднее время проверки, конверсия, просрочки, распределение по
  статусам, динамика по дням и метрики по ученикам. Данные считаются по событиям статусов.
- **Фильтры в URL.** Поиск, модуль, статус, дедлайн и просрочка сохраняются в query-параметрах —
  ссылкой можно поделиться.

## Стек

Vite 8, React 19, TypeScript, React Router 7, TanStack Query, React Hook Form + Zod,
Tailwind CSS 3, Radix UI, dnd-kit, Recharts, Supabase (Postgres + Auth + Realtime), Sonner.

## Быстрый старт (демо-режим)

```bash
npm install
npm run dev
```

Без переменных окружения приложение работает в **локальном режиме**: данные хранятся в
`localStorage`, авторизация настоящая (пароли хешируются PBKDF2), но облако не требуется.
Демо-данные создаются автоматически.

Демо-аккаунты:

| Роль | Email | Пароль |
| --- | --- | --- |
| Ученик | `student@vector.demo` | `vector123` |
| Куратор | `curator@vector.demo` | `vector123` |

Демо-коды приглашений: `VECTOR24`, `STUDY365`. Сбросить локальные данные можно в
**Профиль → Демо-режим → Сбросить демо-данные**.

## Подключение Supabase

1. Создайте проект на [supabase.com](https://supabase.com).
2. Откройте **SQL Editor** и выполните содержимое
   [`supabase/migrations/0001_init.sql`](supabase/migrations/0001_init.sql) целиком. Скрипт
   создаёт enum'ы, таблицы, индексы, триггеры, RLS-политики, RPC-функции и публикацию Realtime.
3. В **Project Settings → API** скопируйте `Project URL` и `anon public key`.
4. Создайте `.env` по образцу [`.env.example`](.env.example):

   ```env
   VITE_SUPABASE_URL=https://<project-ref>.supabase.co
   VITE_SUPABASE_ANON_KEY=<anon-key>
   ```

5. В **Authentication → URL Configuration** укажите:
   - Site URL — адрес приложения (локально `http://localhost:5173`, на Vercel — домен);
   - Redirect URLs — `http://localhost:5173/reset-password` и
     `https://<домен>/reset-password`.
6. Перезапустите dev-сервер. Приложение автоматически переключится на Supabase-адаптер.

### Подтверждение куратора

Новые кураторы создаются с `approved = false` и не могут войти в рабочее пространство, пока
администратор не подтвердит аккаунт. Выполните в SQL Editor:

```sql
select public.admin_approve_curator('curator@example.com');
```

Функция доступна только из SQL Editor / service role.

### Напоминания по расписанию

Миграция пытается зарегистрировать задачу `pg_cron` (`*/15 * * * *`), если расширение
`pg_cron` включено в проекте. Если его нет, включите **Database → Extensions → pg_cron** и
выполните:

```sql
select cron.schedule('vector-reminders', '*/15 * * * *', $$select public.run_reminders()$$);
```

Дополнительно приложение вызывает `run_reminders` при открытии рабочего пространства и раз в
5 минут — это страховка, а не замена расписанию.

### Схема данных и безопасность

- `profiles` — пользователи и роль; поля `role`, `approved`, `email` защищены триггером от
  изменения клиентом.
- `curator_students` — связь «куратор ↔ ученик».
- `invitations` — коды приглашений (7 дней, статусы pending/accepted/revoked/expired).
- `boards`, `modules`, `cards`, `card_events`, `comments` — учебный контент.
- `notifications`, `reminder_events` — уведомления и защита от повторных напоминаний.
- RLS включён на всех таблицах. Изменение карточек идёт только через RPC (`move_card`,
  `create_card`, `update_card`, `add_comment` и т.д.), где проверяются роль, доступ к доске и
  допустимость перехода статуса.

## Деплой на Vercel

1. Импортируйте репозиторий в Vercel; framework preset — **Vite**.
2. Build Command: `npm run build`, Output Directory: `dist`.
3. Добавьте переменные `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` в
   **Settings → Environment Variables** для Production и Preview.
4. После деплоя добавьте домен в Supabase **Site URL / Redirect URLs**.
5. Для SPA-маршрутов добавьте rewrites (если Vercel не определил автоматически):

   ```json
   { "rewrites": [{ "source": "/(.*)", "destination": "/index.html" }] }
   ```

## Ограничения демо-режима

- Данные привязаны к браузеру и не синхронизируются между устройствами.
- Realtime эмулируется событием `storage` (обновления из другой вкладки).
- Восстановление пароля показывает ссылку прямо в интерфейсе, письма не отправляются.
- Загрузка аватаров не реализована: в интерфейсе используются инициалы пользователя.
